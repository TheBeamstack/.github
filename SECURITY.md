# Security Policy

## Reporting a vulnerability

**Do not open a public issue for a security problem.**

Report privately to **askdaoudi@gmail.com** with:

- the affected project and version / commit,
- a description of the issue and its impact,
- steps to reproduce (a minimal proof-of-concept if you have one),
- any suggested fix.

You will get an acknowledgement within **5 working days**. We aim to confirm or
dismiss the report within **10 working days** and to ship a fix for a confirmed
issue as fast as its severity warrants.

Please give us reasonable time to fix and release before any public disclosure.
We are happy to credit reporters (or keep them anonymous) in the release notes.

## Scope

All repositories in the `TheBeamstack` organisation. For a hosted Beamstack
service, issues in the running deployment are in scope; issues in third-party
infrastructure we merely use are not.

## Safe harbour

Good-faith security research on your own instances or accounts, reported
privately as above, will not be pursued by us. Do not access other users' data,
degrade service, or run automated scanning against shared hosted environments.
